# Security policy

Do not open a public issue for a vulnerability involving credentials, license infrastructure, command injection, unsafe executable discovery, network transfer, or artifact handling. Use GitHub's **Report a vulnerability** form only if it is visibly available for the repository. Repository files cannot prove that private vulnerability reporting is enabled. If no private channel is displayed, ask the maintainer to configure one without disclosing exploitable details publicly and do not guess an email address.

Include the affected revision, impact, minimal reproduction steps, and a proposed mitigation when possible. Never attach license files, tokens, private paths, hostnames, private addresses, proprietary solver inputs/outputs, or confidential models. Product vulnerabilities in Ansys software itself must be reported through Ansys's applicable official process, not this independent repository.
