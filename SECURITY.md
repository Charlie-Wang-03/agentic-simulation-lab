# Security policy

Do not open a public issue for a vulnerability involving credentials, license infrastructure, command injection, unsafe executable discovery, network transfer, or artifact handling. After publication, use the repository's GitHub **Report a vulnerability** private-reporting form. If that feature is not enabled, wait for the maintainer to configure a private channel; do not disclose exploitable details publicly and do not guess an email address.

Include the affected revision, impact, minimal reproduction steps, and a proposed mitigation when possible. Never attach license files, tokens, private paths, hostnames, private addresses, proprietary solver inputs/outputs, or confidential models. Product vulnerabilities in Ansys software itself must be reported through Ansys's applicable official process, not this independent repository.
