# Development

Create the project environment with `python tools/bootstrap.py --extras dev`. Keep Ansys imports inside adapter functions or case execution paths. Add a manifest entry with a unique slug, explicit status, prerequisites, units, acceptance checks, and project-relative evidence before exposing a case through the CLI.

## Add or exercise a benchmark

Place a new script in the owning domain's `cases/` directory and reusable code in `common/`. Start its manifest record at `NOT_RUN`; change status only after an authorized execution produces the declared physical evidence. Rebuild the catalog and gallery after manifest changes.

For Fluent work, inspect `cfd/fluent-laminar-channel`, install only the Fluent extra, and verify resource ownership before execution. The case builds a mesh, solves the flow, exports fields, and checks velocity profile, pressure drop, and mass conservation. Preserve its run record when reporting regressions.

## Validate a release candidate

Static checks run without proprietary solvers. In a separately authorized licensed release environment, maintainers may execute representative low-cost cases from Mechanical, Fluent, AEDT, Rocky, and a coupled workflow, recording versions and outcomes. Review every `FAIL` and `BLOCKED` without rewriting history. Confirm license and citation decisions before publication.

## Solver-derived documentation visuals

Explanatory assets under `docs/assets/gallery/`, `docs/assets/showcase/`, and the hero/workflow SVGs are schematics generated by `tools/build_gallery.py`. Genuine result visuals live under `docs/assets/simulations/<domain>/`; the paper/report figures use PNG, while the adjacent SVGs remain lightweight vector summaries. Both are generated by `tools/build_simulation_visuals.py` from sanitized `*.evidence.json` files. Install `.[visuals]` (included by `.[dev]`) to render or check PNGs. The tracked evidence is sufficient for normal offline regeneration; a solver rerun is not part of the documentation build.

Maintainers may use `python tools/build_simulation_visuals.py --import-local` only when the exact ignored local outputs named by the importer are available and their authoritative result remains `PASS`. Review source hashes, units, field shape, and provenance before committing an updated evidence file. Never import or commit solver databases/projects, case/data files, screenshots, runtime logs, license details, absolute paths, or unqualified output. Preserve a failed or blocked source status and choose another representative case instead of manufacturing a contour.

The full migrated benchmark corpus is compiled and manifest/reference-validated. Ruff is applied to the maintained package, tests, tools, and current release-blocking Case J; mechanically reformatting all historical solver scripts is outside the release freeze. The provenance gate rejects unclassified binary/media content and hash drift in reviewed geometry fixtures.
